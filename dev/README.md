### 如何让 Switch 2 Pro 手柄作为 FPS 主力手柄（PC）

###软件篇
Switch Pro 手柄在 PC 上只能通过开发者模式识别，Steam 无法配置摇杆曲线和背键。由于手柄物理结构限制，摇杆输出范围只有 0.8 左右，无法达到标准 1.0 范围。
这套 Python 代码解决了三个问题：
摇杆优化：将摇杆输出从 0.8 映射到 1.0 标准范围，通过算法实现完美圆形输出，充分利用物理移动范围。
背键绑定：支持将背键绑定到任意按键，扩展操作能力。
键盘映射：可将手柄按键映射为键盘按键，方便快速切换麦克风等功能。

###硬件篇
背键改进：Switch Pro 手柄背键高度较低，模具较小不易按压。建议在背键上粘贴普通防撞贴，增加按键高度改善手感。
摇杆帽更换：原装摇杆帽高度较低，可购买第三方摇杆帽增加高度，提升操控精度。

###游戏设置篇
以《远光84》为例推荐设置：
X 轴灵敏度：260
Y 轴灵敏度：160
XY 加速度：200
开镜灵敏度：0.5
// 用小鸡灵狐手柄、SwitchPro手柄，Switch2Pro手柄，反复测试下来，这套设置用的比较顺手。后面刷到 Apex 线性43的设置，发现数值很接近，看来手柄FPS，受摇杆限制，有物理最优解。
// 其他手柄，可根据个人习惯微调各项参数，找到最适合自己的灵敏度配置。一般摇杆回弹力度越大，灵敏度可以越高。例如，小鸡灵狐这种摇杆回弹比较轻盈的，可以灵敏度降低一点。

   https://handheldlegend.github.io/procon2tool/

### 日常使用（推荐）
先运行连接检测界面，确认手柄连上后一键启动主程序：
```powershell
python .\connection_check_gui.py
```
界面逻辑：扫描 2 秒收不到数据就自动尝试激活手柄，再扫一档（总上限约 2~5 秒）；
检测成功立即出结果，失败可点【重新检测】。检测成功后点【启动主程序】即可，
也可以勾选"连接成功后自动启动主程序"。

主程序启动后，**记得点一下游戏窗口**再操作手柄——键盘映射（pyautogui）是发给当前焦点窗口的。

### 校准数据本地化（不再每次启动都校准）
主程序 Switch2ProControllerWorkOnPC.txt 会保存校准结果，下次启动直接复用：

1. 启动时先读取本地校准文件 `Switch2ProControllerWorkOnPC_calibration.json`（打印完整路径与保存时间）
2. 本地**没有**校准数据（或文件损坏、范围异常）→ 直接进入完整校准流程
3. 本地**有**校准数据 → 显示 3 秒倒计时：
   - 倒计时期间按下手柄上**任意按键** → 重新校准
   - 倒计时结束**没有按键** → 直接使用本地数据启动（不用碰手柄）
4. 校准有效时才写入本地文件；校准无效（摇杆没转到位）不会覆盖已有数据

**行程体检**：校准完成后会自动检查四个方向行程是否均衡。若某方向明显偏小
（例如"向右只量到 0.724，最强方向是 0.806"），会提示重新校准，因为那会导致
该方向推不到满偏、其他方向外部死区变大。建议校准时把摇杆**贴着边缘慢慢转 3~5 圈**。

想强制重新校准：删掉 `Switch2ProControllerWorkOnPC_calibration.json`，或启动后在 3 秒倒计时内按任意键。

### 手柄按键数量不同 / 抓到虚拟手柄
主程序按名字优先挑选 `If_Hid` / `Switch` 手柄，避免抓到 Steam 或 vgamepad 创建的
虚拟 XBOX 手柄（虚拟手柄只有 11 个按键，会让 `get_button(13)` 之类越界并刷屏报错）。
若要用其它手柄，改主程序顶部的：
```python
PREFERRED_JOYSTICK_NAMES = ('If_Hid', 'Switch')
```

### 校准本地化回归测试
```powershell
python .\test_calibration_localization.py
```
覆盖 4 个场景：无数据→自动校准并保存 / 有数据+倒计时内按键→重校准覆盖 /
有数据+不按键→沿用且不重写 / 数据损坏→自动修复。

⚠️ **注意**：这个测试会写入一份**假手柄**的校准数据（`joystick_name` = `FAKE Switch2 Pro Controller`），
**跑完必须删掉 `Switch2ProControllerWorkOnPC_calibration.json`**，否则真实手柄会沿用假数据。

## StickLab —— 手柄调参中心（Web 界面）

面向 Apex 的职业级调参工具：摇杆曲线、死区、双曲线（开镜切换）、按键映射、校准。

### 启动
```powershell
python .\sticklab\webapp.py
```
默认地址 `http://127.0.0.1:8899`（端口被占用会自动顺延），浏览器自动打开。

### 五个功能页

| 页面 | 作用 |
|---|---|
| **摇杆曲线** | 实时曲线画布、死区形状（圆形/十字/方形）、响应曲线（线性/幂/经典/动态）、增益、转向增益、圆方混合、平滑、行程补偿模式 |
| **校准** | 中心点 + 四方向行程测量，自动给出最短方向警告与推荐补偿模式，结果可视化 |
| **按键映射** | 物理键（21 键）→ 虚拟 XInput 按键（每键最多 2 个）+ 键盘按键 |
| **预设方案** | Apex 追踪流 / 甩枪流 / 精准微调流 / 方形手感 / 原始直通，一键应用 |
| **诊断** | 实时链路数据（原始值 → 死区后 → 曲线后 → 输出）、可拖拽的虚拟摇杆 |

### 核心设计（针对 Apex 痛点）

1. **行程补偿 global_min**：Switch2 Pro 物理行程仅约 ±0.73，用最短方向做统一基准，
   保证四方向反应一致、圆轨迹不畸变，任何方向都能推到 1.0
2. **双曲线（开镜切换）**：按住 ZL 自动切换到 ADS 参数（更低增益、更细腻），
   相当于手柄版的"开镜灵敏度"
3. **转向增益 turn_boost**：只放大 0.6 以上幅度，帮助大角度转身，**不影响精细追踪**
4. **死区形状可选**：圆形（保方向，追踪首选）/ 十字（消斜向串扰）/ 方形（对角更快）

### 预设实测曲线差异（推杆百分比 → 输出）

| 预设 | 25% | 50% | 75% | 定位 |
|---|---|---|---|---|
| Apex 追踪流 | 0.251 | 0.511 | 0.786 | 近线性平滑追踪（推荐） |
| Apex 甩枪流 | 0.320 | 0.588 | 0.891 | 小幅度更灵敏 |
| 精准微调流 | 0.135 | 0.359 | 0.617 | 中心更细腻 |
| 原始直通 | 0.250 | 0.500 | 0.750 | 1:1 对比基准 |
